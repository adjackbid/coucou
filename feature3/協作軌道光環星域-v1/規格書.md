# 協作軌道光環星域實作規格

版本 1.0.0　定稿日期 2026 年 10 月 6 日　適用專案 CouCou Teamwork

在公司總覽新增「星域」模式，讓使用者看見多個 Agent 在同一個宇宙中漂浮、彼此連結及傳送資料。Agent 以光環和發光核心代表，同團隊自然靠近；背景星塵與柔光平常持續緩慢移動。使用者可以旋轉視角、縮放和選擇節點，查看工作狀態與協作關係。

本規格以同資料夾的 `index.html` 與 `examples/agent-orbit.fragment.html` 為視覺和動作基準。條文中的「必須」為接入要求；標為「參考值」的數字可在實際產品尺寸下微調，但須保留相同觀感。

## 一 產品範圍

星域是既有 Office 與中二模式之外的顯示選項。團隊、Agent、任務、Token、成本和活動紀錄沿用原有資料，顯示模式不改變任務流程。切換顯示時應保留使用者正在查看的團隊和 Agent。

星域節點不使用 Mochi 身體、五官、桌椅或魔王。原有 Teamwork 商標可保留。場景是一整個連續空間，各團隊不使用卡片、面板或矩形邊框分隔；軌道線是空間提示，可以穿過其他軌道。

這輪交付是設計與參考實作。真實資料 adapter、動態增加團隊、事件訂閱與正式元件的清理生命週期，須由接手 AI 在專案內實作。

## 二 頁面構成

| 區域 | 必須呈現的內容 |
| --- | --- |
| 原有導覽 | 保留公司總覽、團隊和既有功能入口 |
| 頁首 | 星域名稱、實際團隊數與 Agent 數、顯示模式切換 |
| 場景工具列 | 暫停漂浮、減少動態；傳送示範僅限示範或開發環境 |
| 場景 | 光環節點、團隊標籤、軌道、常駐關係連線、流動星塵和柔光 |
| 相機工具 | 左轉、右轉、斜視、俯視、側視、縮放和全景 |
| 選擇資訊 | 團隊、Agent 名稱、角色、工作狀態、直接關係數 |
| 資料狀態 | 正式版顯示實際連線或資料更新狀態；示範版標明示意資料 |

場景上方標籤和下方操作區須有留白，光環與名稱不得被控制列蓋住。主畫面用可讀的 HTML 標籤疊在 3D 投影之上，文字不跟著相機扭曲。

## 三 光環 Agent

每位 Agent 由明亮光芯、細主環、較淡的分段外環和柔光構成。中心維持透光感，不能變成不透明球體。每個節點使用穩定顏色，旁邊的名稱和狀態符號提供辨識，不能只靠顏色。

參考頁的光環是面向鏡頭的 billboard，節點位置則是真實三維座標。因此改變相機時仍看得到完整光圈，距離改變會造成大小、位置和遮擋的變化。可以使用其他繪圖引擎，但須保留這個可辨識性。

| 項目 | 定稿參考值 |
| --- | --- |
| 貼圖 | 程式生成 256 × 256 RGBA，透明四角，不下載外部圖片 |
| 畫圖局部座標 | 128 × 128 邏輯單位，生成時放大兩倍 |
| 主環半徑 | 38 邏輯單位，彩色細線加淡白色內緣 |
| 外環半徑 | 49，三段短弧與小亮點 |
| 內側點環半徑 | 27，低亮度細點 |
| 中心光芯 | 軟光半徑 17，中心白點半徑 2 |
| 世界尺寸 | 約 1.5 場景單位，呼吸振幅 2.4% |
| 外環旋轉 | 約 0.13 rad/s，依節點交錯正反方向 |
| 呼吸 | 角頻率 0.64 rad/s，約 9.8 秒一輪，亮度柔和變化 |
| Agent 名稱 | 參考 12px，最低 11px，保持水平 |
| 角色名稱 | 選取、鍵盤焦點或滑鼠停留時顯示 |

示範顏色依序為藍 `#65b5f2`、綠 `#53d5ae`、紫 `#aa8ae9`、金 `#fac455`、粉 `#ed96c6`。正式版應以穩定 Agent ID 保存顏色，不能因清單排序改變就換色。團隊顏色主要用於軌道、常駐連線和團隊標籤。

### 工作狀態

參考頁包含工作中、等待協作、已完成。工作中使用藍色小點；等待使用金色小點；已完成使用綠色小點與勾號。選擇資訊必須顯示狀態文字。

正式接入亦須能表達待命、錯誤和離線：待命用低亮度中性標記，錯誤用錯誤符號和文字，離線用低亮度斷續環和文字。這三個狀態是接入契約要求，未在目前十三節點範例中展示。未知狀態顯示「狀態未知」，不得自行判為工作完成。

## 四 團隊分布與漂浮

同團隊的成員圍繞共同中心，團隊之間留出較大的空間。Leader 在群落中心附近，其他成員沿不同角度的軌道分布。空間關係要清楚，但不能像固定表格或卡片排列。

| 動作 | 定稿參考值 |
| --- | --- |
| 節點上下漂浮 | 振幅約 0.22 單位，角頻率 0.78 rad/s |
| 成員緩慢繞行 | 約 0.022 rad/s，不同團隊可反向 |
| Leader 小幅游移 | 水平方向振幅約 0.17，角頻率 0.12 rad/s |
| 軌道 | 每團隊兩條淡薄橢圓投影；一般半徑約 2.15，五人群約 2.75 |
| 個體相位 | 每位 Agent 使用不同相位，避免整群同步上下移動 |

空間位置、連線端點和點擊命中區必須每次使用同一份節點座標。群落與角色名稱須避讓其他名稱、光環和工具列；若空間不足，優先移動標籤或調整群落間距。

四團隊位置僅是附錄樣本，正式版不得寫死這四個團隊名稱、座標或十三個節點。新團隊加入時，應維持已有群落的穩定位置，將新群落放入空位或緩慢重排。單人團隊可只有一個節點和軌道，不必為了連線補出假成員。

## 五 常駐協作連線

平常就能看見 Agent 之間的光線。即使沒有新訊息，或已暫停漂浮，關係線仍須存在。

| 關係 | 顯示規則 | 語義 |
| --- | --- | --- |
| `team_connection` | 同團隊 Leader 與每位成員持續連結 | 團隊關係，不代表正在傳送資料 |
| `workflow` | 真實工作流程或既有協作關係，有資料時顯示 | 已知協作路徑 |
| `communication` | 真實傳送事件需要的路徑，至少維持到光流結束 | 實際資料傳送 |

沒有 Leader 的團隊，使用穩定 ID 決定視覺中心，僅作成員關係佈局，不修改角色職務。兩人團隊一條核心關係線，五人團隊四條核心關係線。常駐關係按端點組合去重；訊息的傳送方向另存於事件，不能因關係線無方向而遺失 from/to。

不得為美觀任意補畫跨團隊協作。真實跨團隊訊息可在兩個群落間畫長連線；團隊內線和跨團隊線要使用同一投影管線。

參考曲線採用三維拱線，`a` 和 `b` 是當下端點位置，`u` 在 0 到 1：

```text
P(u) = a × (1 − u) + b × u + (0, sin(πu) × 0.8, 0)
```

光流沿整條曲線移動；常駐線可略縮短兩端，避免蓋住光芯。參考頁顯示 u = 0.09 到 0.91 的常駐段，以 33 點取樣。

一般核心線寬約 1.15px，外暈約 3.8px；次要流程線亮度略低。選擇 Agent 後，其直接連線提升至約 1.7px 核心、5px 外暈，其他團隊降低亮度。核心關係線不能被「額外交付連線」的開發選項全部隱藏。

## 六 資料傳送效果

收到真實傳送事件後，亮光從傳送端沿曲線前進至接收端，留下短拖尾。抵達時接收端出現短暫外擴光環，事件文字標明傳送方向與內容摘要。節點漂浮或使用者改變角度時，光流仍沿同一條協作線移動。

| 動作 | 定稿參考值 |
| --- | --- |
| 單次光流行進 | 1700ms |
| 光流拖尾 | 8 個漸淡光點，每點相隔 0.016 的路徑比例 |
| 接收光環 | 約 290ms，外擴後消失 |
| 示範批次 | 三筆，起始間隔 900ms，總結束時間約 4300ms |
| 一般配色 | 淺藍或薄綠；選擇節點時保持方向清楚 |

正式版傳送由事件資料觸發，不使用固定示範批次。重複 event ID 或 message ID 不應造成同一訊息重播。接收事件可比本機動畫早到，資料狀態以真實事件為準，動畫只是表達。

事件過密時，可以合併同一路徑的視覺效果並保留實際訊息計數，避免畫面堆滿粒子。這項合併屬正式接入要求，參考頁尚未實作。不得用 Token 累計或節點呼吸頻率推論資料傳送。

## 七 背景持續流動

星域平常持續緩慢移動背景。使用者不拖曳相機、沒有新訊息時，也必須看得到星塵漂移。柔光移動速度比節點更慢，形成前後深度。使用者拖曳時的相機投影與背景自身漂移可同時發生，兩者不能互相代替。

| 層 | 定稿參考值 | 行為 |
| --- | --- | --- |
| 深色底 | `#030916`、`#090f21`、`#15253a` | 穩定的深色空間，不出現四邊黑框或背景接縫 |
| 星塵 | 780 顆，示範固定種子 92，球形分布半徑 21 到 48 | 緩慢旋轉並小幅上下流動，按距離呈現視差 |
| 星塵旋轉 | 0.0025 rad/s，約 42 分鐘一整圈 | 不作快速飛行或速度線 |
| 星塵垂直流動 | 振幅 0.7 單位，角頻率 0.025 rad/s | 約 251 秒一輪 |
| 柔光 | 三層，藍 `#507cae`、紫 `#8270b6`、青 `#3c9e99` | 寬而淡的雲狀光暈，無硬邊 |
| 柔光游移 | 水平角頻率 0.018、垂直 0.014 rad/s | 各層相位不同，低幅度移動 |
| 柔光轉動 | 角頻率 0.012 rad/s，角度振幅 0.08 rad | 比 Agent 外環慢得多 |

背景和節點共用可暫停的 ambient 時間，傳送效果使用自己的事件時間。WebGL 與 Canvas 後備必須採用相同的星塵漂移公式，不能切換後重新出現一張靜態星空。

### 暫停與減少動態

「暫停漂浮」停止背景、柔光、節點游移、呼吸和裝飾軌道亮點。常駐連線、狀態、選擇和相機操作仍有效；新資料仍會更新，短暫的事件傳送效果可完成。這個控制不是暫停 AI 執行或中斷任務。

「減少動態」停止所有持續動作，傳送以靜態加亮、摘要和接收狀態呈現，取消光流拖尾與外擴動畫。預設尊重作業系統的 `prefers-reduced-motion`，操作介面亦須可手動切換。

頁面不可見或場景離開可視區時，停止動畫 frame。返回時以最新資料恢復；不要一次重播離開期間所有過期效果，也不要用巨大的時間差令節點突然跳躍。

## 八 相機與選擇

| 操作 | 行為與參考值 |
| --- | --- |
| 滑鼠拖曳 | 水平旋轉 yaw，垂直調整 pitch，不拖動網頁文字 |
| 滾輪 | 連續縮放，僅在星域內攔截滾輪 |
| 單指拖曳 | 改變相機角度 |
| 雙指 | 依指距比例縮放 |
| 相機按鈕 | 不依賴拖曳，可鍵盤操作 |
| 視野角 | 42° |
| 預設斜視 | yaw 0.14 rad，pitch 桌面 0.55、小型場景 0.25 rad |
| 俯視 | pitch 1.18 rad |
| 側視 | yaw 0.78、pitch 0.14 rad |
| 拖曳角度範圍 | yaw −1.35 到 1.35，pitch 0.08 到 1.35 rad |
| 縮放範圍 | 0.65 到 2.2，顯示 65% 到 220% |
| 全景 | 相機恢復預設角度與 100%，保留工作資料和 Agent 選擇 |

上表是目前有限角度轉動，不是 360° 無限制環繞。正式版如擴大角度範圍，須另檢查標籤、命中區和群落遮擋，不能直接宣稱附錄已驗證全角度。

點選光圈顯示團隊、名稱、角色、狀態和直接關係數，並加亮直接連線。名稱維持水平；縮放會調整節點投影尺寸，文字仍維持可讀。將拖曳誤差和點擊區分開，參考頁以移動超過 5px 判為拖曳。

選擇和相機可儲存在本機 UI state，不能把這些偏好寫回 Agent 工作資料。參考頁的 `window.openai.widgetState` 僅是預覽保存方式；正式版換成專案自己的 UI store。

## 九 響應式與可讀性

參考頁以完整桌面介面呈現，側欄在畫面寬度小於 760px 時隱藏。場景寬度小於 490px 時，四團隊由左右分布改為直向排列，操作列換行，支援 320px 寬螢幕。

桌面場景高度參考 668px，小型場景為 1080px。這是參考頁的可視布局，不是正式產品必須寫死的視窗高度。正式版應使用實際容器尺寸計算群落分布與相機距離。

標籤最低 11px。手機點擊目標約 44px，不能為了維持十三節點而把字縮到不可讀。團隊標籤、Agent 名稱和相機操作區不能重疊。主畫面縮放超出全景時，允許部分節點離開畫面，使用者可用全景恢復。

外層介面依產品的深淺色主題變化；宇宙場景維持深色，確保光環和光流可見。

## 十 資料契約與接入

資料契約見 `data/orbit-contracts.ts`。它是建議的前端 adapter 契約，並非 CouCou 現有 API 的宣告。接手 AI 必須先確認實際資料模型，再將既有欄位映射至以下內容。

| 資料 | 必要欄位 | 目的 |
| --- | --- | --- |
| Team | `id`、`name`、`color`，可有 `leaderAgentId` | 群落辨識與佈局 |
| Agent | `id`、`teamId`、`name`、`role`、`status`、`color` | 節點和真實狀態 |
| Relation | `id`、`fromAgentId`、`toAgentId`、`kind` | 常駐關係和工作路徑 |
| 傳送事件 | `id`、`type`、`messageId`、`fromAgentId`、`toAgentId`、`summary`、`occurredAt` | 方向、去重、事件摘要 |
| 狀態事件 | `id`、`agentId`、`status`、`occurredAt` | 更新節點工作狀態 |
| ViewState | `yaw`、`pitch`、`zoom`、`paused`、`reduceMotion`、`selectedAgentId` | 本機介面偏好 |

目前樣本有四團隊、十三位 Agent、九條核心團隊關係和三條額外流程關係，共十二條。`example-events.json` 是合成事件時序，用 `offsetMs` 播放；正式資料不得依這個固定時序製造活動。

正式接入應分開資料、佈局、繪圖和 UI 四層。資料 adapter 接收真實快照與事件；佈局維持穩定三維位置；繪圖只讀當下位置與視覺狀態；UI 負責相機、選擇和資訊。Agent 刪除後移除其關係線和過期效果，重連不重複訂閱，不保存完整對話內容到視覺設定。

## 十一 繪圖與效能

參考頁用原生 WebGL 畫深度光環、軌道、粒子，Canvas 畫柔光和投影曲線，HTML 畫標籤和按鈕。原生 WebGL 是參考方式；正式版可用專案既有繪圖方案，效果和操作必須相同。

光環與粒子使用透明貼圖和加法混色，不能留下矩形底。WebGL canvas 採用 premultiplied alpha，顏色與透明度分開設定 blend，避免半透明光暈在瀏覽器合成時變暗。共用光環貼圖，勿每 frame 重新產生貼圖。

參考刷新上限約 30fps，裝置像素比上限 1.7。正式版可調整刷新與星塵數，但互動時要保持可用；應先減少背景粒子與模糊，而不是讓狀態、核心連線或標籤消失。不得聲稱目前參考頁已驗證大量團隊或硬體效能。

WebGL 初始化失敗或 context lost 時，切換到 Canvas 後備，保留光圈、連線、相機、資料選擇與背景慢移。正式元件卸載時，清理 requestAnimationFrame、observer、pointer listener、事件訂閱及 GPU 資源，避免切換模式累積多個迴圈。

## 十二 實作順序

1. 在公司總覽加入星域切換，建立同一宇宙場景，接入真實團隊與 Agent 清單。
2. 完成光環、名稱、狀態與穩定群落分布，再完成相機投影與點擊。
3. 加入常駐核心關係線，確認每個多人成員群都連通。
4. 接入真實訊息事件，加入方向光流、接收回饋和事件去重。
5. 加入背景星塵與柔光慢移，完成暫停、減少動態與不可見時停止。
6. 完成響應式、Canvas 後備、清理生命週期與既有模式回歸，依驗收清單交回截圖和結果。

## 十三 參考來源與驗收

定稿來源為 `examples/agent-orbit.fragment.html`；具體數值另列在 `data/visual-config.json`。主要函式對照如下。

| 函式 | 接手時參考的內容 |
